# Mihomo NodePool

中文节点管理网页，使用 Vue 3、TypeScript、Go、内嵌 Mihomo 和外部 MySQL。通过 Docker 单容器部署。

## 功能

- 导入订阅 URL、本地 Clash YAML/JSON 文件、Base64 订阅和 Mihomo 支持的节点分享链接；支持批量来源。
- 按完整连接配置生成指纹，跨来源去重。节点名称不参与指纹，密码、UUID 和传输参数参与；来源与原始名称保留。
- 节点默认卡片展示，可用图标切换到列表；支持分页、名称、地址、协议、地区网格多选、可搜索分页来源和健康状态筛选。国旗 SVG 随应用打包，出口显示 IP 及“国家 · 省／州 · 城市”。
- 全局与单来源名称排除正则；默认排除剩余流量、到期说明等信息节点。被排除节点不进入有效列表。
- 订阅刷新和成功后的节点检测按各自加入时间每 6 小时稳定错峰，限并发、持久化队列与任务租约，重启后恢复。
- 使用内嵌 Mihomo URLTest；失败检测按 1、2、4、8、16 小时退避，之后最多 24 小时。连续 7 天未成功则屏蔽，成功后解除屏蔽并恢复正常排期。通过节点查询出口信息，不包含 AI 平台解锁检测。
- 用户名登录、管理员创建账号及调整额度；普通用户管理自己的上传来源，支持提供方入口和关注。
- 节点跨页多选、整来源按剩余额度截取并保存组合订阅；默认账号合计 200 个唯一节点、3 个来源、1 条组合。来源可设置历史唯一领取账号人数上限。
- 个人 `/sub/{token}` 支持 Clash／Mihomo YAML 和 v2ray 兼容 URI Base64；可删除或重置令牌，客户端刷新无需 Cookie。
- 版本文字读取真实版本，管理员可查看 GitHub Release、更新、回退和立即重启；**回退只切换程序，不处理数据库**。
- 下拉和筛选浮层自绘，支持键盘和触屏；亮暗首次跟系统，太阳／月亮图标切换后保存在浏览器中。所有表单统一标签、输入、说明的行布局。
- 节点、来源、提供方、订阅、账号及管理员页面使用独立路由；分页、筛选及视图保存在 URL，支持直接访问、刷新和浏览器前进后退。

节点请求、国家查询的结果受部署机器的网络、节点可达性及第三方查询服务影响。列表中的延迟是代理 HTTP 测试延迟，不是 ICMP ping。

完整需求和接口见 [requirements](docs/requirements.md) 与 [API](docs/api.md)。

## Windows 本地运行

要求 Go 1.26+、Node.js 24 和 npm；数据库使用现有 MySQL 8.0+（CI 使用 MySQL 8.4）。

先准备配置：

```powershell
Copy-Item .env.example .env
```

编辑 `.env`，填写 `MYSQL_HOST`、`MYSQL_PORT`、`MYSQL_USER`、`MYSQL_PASSWORD`、`MYSQL_DATABASE`。建议设置至少 8 字节的 `ADMIN_PASSWORD`。然后执行：

```powershell
.\scripts\start.ps1 -Build
```

打开 `http://127.0.0.1:8080`。按 Ctrl+C 停止。后续不修改代码时可运行 `.\scripts\start.ps1`（去掉 `-Build`）。

管理员用户名为 `admin`。未设置初始密码时，首次启动会生成 `data/admin-password`，日志只显示路径；可在本机读取后登录。连接数据库后管理员账号和密码持久化，随后更改环境变量不会覆盖数据库中的密码，可在账号设置修改。没有 MySQL 时仅能使用原管理员连接提示，不能保存业务数据。

程序读取当前工作目录 `.env`，已有进程环境变量优先；可用 `NODEPOOL_ENV_FILE` 指定文件。Windows 启动脚本自动使用项目根目录配置。

启动脚本保存为带 BOM 的 UTF-8，同时兼容 Windows PowerShell 5.1 和 PowerShell 7 的中文解析。

## 开发与构建

```bash
npm ci --prefix frontend
node scripts/build.mjs
```

产物为 `build/nodepool`，Windows 为 `build/nodepool.exe`，已包含前端和 Mihomo。运行产物即可访问网页。

开发时另开终端运行：

```bash
npm run dev --prefix frontend
```

前端地址 `http://127.0.0.1:5173`，代理 API 到 `127.0.0.1:8080`。后端仍运行上述构建产物；修改 Go 代码后重新构建并启动。

## Docker

`.env` 连接现有 MySQL；应用会在指定库中创建 `np_` 前缀表，需要建表和读写权限。旧版本升级需要 `ALTER` 权限：补充地区／屏蔽字段、来源人数上限、用户／关注／领取／订阅表，并把 URL 唯一索引迁移为用户＋URL 哈希；管理员 ID=1、既有来源／缓存／节点身份和检测历史保留。历史健康节点以最近检测时间初始化成功时间，其余以入库时间初始化失效基准。请使用独立数据库，并确保容器可访问实例。

从源码构建：

```bash
docker compose up -d --build
```

有正式版本后，使用 GHCR 镜像：

```bash
docker compose pull
docker compose up -d --no-build
```

默认网页端口 8080，可用 `HTTP_PORT` 更改。持久化目录 `/app/data` 保存自动生成的管理员密码等运行文件；业务数据在 MySQL 中。容器以 UID 1000 运行应用，启动脚本只在准备目录时使用 root。

当前按单应用实例部署。不要同时启动多个实例来扩容；全局并发上限及更新操作按单实例管理。

## 设置与数据行为

- 全局排除正则在运行设置中编辑，来源可单独追加规则。正则变化使用已保存内容重算，不刷新全部订阅链接。
- 相同配置在不同来源中只显示一行，展开节点详情可以查看来源和原始名称。同地址不同凭据不会合并。
- 删除来源只移除该来源关系；其他来源引用的节点继续保留。停用来源后它独有的节点不进入有效列表和检测。
- 订阅抓取或解析失败保留上次节点，来源卡片显示错误；自动刷新失败 15 分钟后重试。
- 批量新节点首次检测在 30 秒窗口内错峰排队；成功后恢复 6 小时稳定错峰，失败进入指数退避。错过周期只补一次。
- 国家、省／州和城市通过对应节点获取，正常缓存 24 小时；旧记录缺少地区时会在下一次检测补查。第三方查询服务失效不会将可用节点判为不可用。
- 连续 3 次失败标为不可用，每次失败都会推进退避；一次成功即可恢复健康并清零失败次数。连续 7 天未成功的节点不进入有效列表、筛选选项和普通检测队列；仍可通过明确节点 ID 的检测 API 手动复测，成功后重新显示。

## 用户与订阅

管理员在“用户管理”创建账号，可调整节点／来源／订阅三项正整数额度。普通用户无需审核即可上传来源；全局设置、更新和手动检测仅管理员可操作，检测入口位于节点详情。暂不开放自助注册。

节点卡片默认点击查看详情；点击“选择节点”进入整卡选择模式，选区跨页保留，也可选择整个来源。整来源弹窗同时展示已有单选节点和来源选择状态。默认额度按账号全部组合合计，重复节点只计一次；整来源按节点顺序填剩余额度，超过时提示截断。保存的是固定节点快照，后续来源刷新不会自动替换为未选择的新节点。

来源分开显示“当前使用人数”和“历史领取／上限”。当前使用按仍有组合引用来源的启用账号去重，删除最后一个引用或覆盖为其他来源后减少。历史唯一领取人数不因删除组合或取消关注回收；同账号多节点、多个组合、客户端刷新只计一人，保存失败不占名额，降低上限不影响已领取账号。

“我的订阅”可查看组合、编辑节点、切换规则、复制自动／Clash／v2ray 地址、删除或重置链接。数量或节点满额时，仍可选好节点，在保存弹窗选择覆盖已有组合；覆盖保留原订阅链接。令牌地址允许客户端下载节点凭据，应只交给自己的客户端；重置／删除后旧链接立即失效，停用账号会永久撤销当时的旧令牌。

Clash 导出保留完整代理配置。v2ray 仅输出能保真表达的 URI 节点，不能转换的配置会跳过并通过 `X-Subscription-Skipped` 报告数量，全部无法输出时返回 422；复杂传输／插件配置请使用 Clash 格式。此项目不提供 sing-box JSON。

所有账号直接拥有只读的“官方默认规则”，新建组合订阅默认选中，无需先复制。官方规则沿用本机“订阅共享”的完整分流规则，包含国内直连、广告拦截、自动选择和故障转移；可查看或复制成私人组合。私人规则工作台支持搜索、分页、逐条增改、顺序调整、文本编辑和撤销本次修改，DNS 独立设置。DNS 启用但留空时使用 `223.5.5.5`、`119.29.29.29`、`8.8.8.8`，关闭则不写入 DNS；分流关闭时合并缓存来源的本地规则与策略组。只影响 Clash，v2ray 保持原样。可显式选择不绑定；旧订阅不强制迁移。仍被订阅使用的私人规则须先解绑再删除。

地区筛选以勾选标记、已选名称标签及数量显示选择情况，收起后仍显示所选地区。当前选区按真实来源名称分组，可逐项移除。弹窗仅在遮罩上按下并松开的短点击时关闭，从内容区拖出不会误关闭。

## 配置

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `HTTP_ADDR` | `:8080` | 应用监听地址 |
| `DATA_DIR` | `./data` | 本地持久化目录，容器内为 `/app/data` |
| `ADMIN_PASSWORD` | 自动生成 | 初始管理员密码，8–1024 字节；持久账号初始化后在网页修改 |
| `MYSQL_HOST` | 空 | 现有数据库地址 |
| `MYSQL_PORT` | `3306` | 数据库端口 |
| `MYSQL_USER` | 空 | 数据库用户 |
| `MYSQL_PASSWORD` | 空 | 数据库密码 |
| `MYSQL_DATABASE` | 空 | 数据库名 |
| `MYSQL_TLS` | `false` | `true` 启用证书验证的 TLS |
| `NODEPOOL_ENV_FILE` | `.env` | 本地配置文件路径 |
| `UPDATE_GITHUB_TOKEN` | 空 | 读取私有仓库 Release 的令牌，需有目标仓库只读权限 |

凭据不返回前端；来源 URL 与节点原配置不会由列表接口回显。来源内容和凭据存储在你配置的 MySQL 中，数据库备份与访问权限由部署者管理。

## 更新、回退与发布

左上角版本文字可查看实际版本；管理员可打开发布说明和历史版本。Linux 正式版本可下载对应架构发行包，验证 `checksums.txt`，保留本地 `.backup` 后原子替换运行程序。点击“立即重启”后进程退出，Docker 的 `restart: unless-stopped` 负责拉起。

Windows 本地版本可以查看发布信息，但不执行在线替换或重启。`dev` 构建不允许在线安装；使用正式 `vX.Y.Z` 构建才开放。

回退可以恢复本地上一次程序备份，或下载安装可用的历史版本。回退不回滚 MySQL。容器内替换的程序不会改变镜像：重新创建容器时会回到所选镜像版本，因此重建时请选择对应版本的镜像。

推送稳定标签 `vX.Y.Z` 触发工作流，生成 Linux AMD64/ARM64 发行包、校验文件，以及 GHCR 多架构镜像和 GitHub Release。普通提交和 PR 只运行 CI，不发布版本。首次真实发布与真实私有资产下载仍需发版后验证。

## 验证

```bash
npm run typecheck --prefix frontend
node scripts/build.mjs
cd backend
go test ./...
go vet ./...
```

真实数据库测试仅允许使用名称以 `nodepool_test` 开头的隔离测试库。设置 `MYSQL_TEST_DSN` 后运行；容量用例额外设置 `NODEPOOL_CAPACITY_TEST=1`。这些用例会清空测试库中的 `np_` 数据，禁止指向业务库。

浏览器测试位于 `e2e/`，运行前构建应用、安装测试依赖及 Chromium，并设置连接隔离库 `nodepool_browser_test` 的 MySQL 环境变量。运行 `node e2e/smoke.mjs`，覆盖账号登录、角色权限、建号、用户来源、关注、组合裁切／快照、匿名下载、令牌撤销，以及三种导入、去重、排除、搜索、真实代理延迟和移动布局。`npm run test:browser --prefix frontend` 为使用测试接口夹具的控制台回归，不能代替真实后端验收。

- `/healthz`：无需登录的存活检查。
- `/readyz`：数据库和表结构就绪检查。
- `/api/v1/system`：普通用户获取版本，管理员另获取内核、数据库和任务状态。
