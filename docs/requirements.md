## 产品与部署

- 项目名：Mihomo NodePool；仓库 LectWolf/mihomo-nodepool，初始为私有仓库。

- 已核对参考源码提交：e7f208eae7125e02ba3ccde882fd7ce99aa51f79。参考源码仅存会话临时目录，不提交到本项目。

## 第一版节点管理

- 支持订阅链接、本地文件、节点分享链接导入。
- 面向数百个来源、数千个节点；容量验收目标为 500 个来源、10,000 个唯一节点。受控测试不代表真实代理检测耗时。
- 来源与唯一节点分开存储，用关联记录保留原始名称和来源。
- 去重以规范化完整连接配置的指纹为依据，忽略显示名称；密码、UUID、TLS、SNI、传输等有效连接参数参与判断。
- 同名、同地址或相同出口 IP 本身不构成去重依据。
- 删除来源不影响其他来源仍引用的节点；来源刷新失败保留上次成功内容。
- 统一节点列表，支持分页、搜索、协议、来源、国家和延迟筛选。
- 自带可配置名称排除正则，参考默认关键词：剩余、到期、过期、流量、官网、套餐、重置、expire、traffic、website、remaining。
- 排除在生成有效节点集合前执行；排除节点不进入正常列表、选择范围或未来订阅输出。可保留原始来源快照用于重新计算。
- 第一版只展示、管理与检测，不实现节点选择或订阅输出。

## 调度与检测

- 订阅来源刷新和唯一节点延迟检测分别每 6 小时执行。
- 来源刷新按来源加入时间排期，节点检测按唯一节点首次入库时间排期。
- 增加稳定错峰、任务队列及并发上限，处理同批导入造成的时间集中。
- 首次检测排队执行；重复节点只检测一次，已有节点刷新后保留检测身份和排期。
- 持久化下次执行时间；重启后恢复队列，错过的周期合并补跑，避免补跑风暴。
- 参考项目通过 Mihomo URLTest 检测，默认 generate_204 测试地址、5 秒超时、16 并发，失败重试一次，健康状态使用连续失败和恢复阈值。
- 沿用参考检测方法，周期改为用户要求的 6 小时；并发上限可配置。
- 经对应节点获取出口 IP 和国家，单独缓存；不做 OpenAI、Anthropic、Gemini 或 Grok 解锁检测。

## 版本、更新和回退

- 显示版本号，点击可查看发布说明、更新、回退和立即重启。
- 按参考项目方式从 GitHub Release 下载对应架构程序包，校验后备份并替换运行文件。
- 立即重启通过 Linux 进程退出，由 Docker restart 策略拉起。
- 支持恢复上次本地程序备份及安装允许的历史 Release。
- 用户明确要求：回退只切换程序文件，不备份、回滚、迁移或校验数据库版本。
- 版本发布自动生成 GHCR 多架构镜像和 GitHub Release 发行包、校验文件。
- 初始准备阶段仅配置发布工作流，不创建版本标签、不发布镜像、不部署。
- 容器内更新与镜像版本分开：重建容器会使用所选镜像内的程序版本。
