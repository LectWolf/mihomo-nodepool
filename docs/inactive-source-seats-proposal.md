# 不活跃来源席位回收提案

状态：待确认，尚未实现。本轮没有改变历史领取名额、下载资格或删除订阅后的处理。

建议为来源增加可选的席位租期：默认连续 30 天没有有效活动进入 7 天宽限期，宽限期结束后释放有效席位。来源所有者可关闭回收或调整周期；历史来源默认关闭，开启时给已有领取者完整观察期，不按旧创建日期立即清退。

## 活动判定

- 按 `(source_id,user_id)` 记录，跨该用户多个组合取最近一次活动。
- 成功的个人客户端下载中，确实输出了该来源的节点，才续期；输出失败、来源被过滤、仅访问网页、后台刷新来源和节点检测都不续期。
- 网页可提供明确的“保留席位”操作，供正常使用但客户端更新不频繁的用户续期；不能用一次登录自动续全部来源。
- 这是订阅更新活跃度，服务端看不到用户实际代理流量。客户端持续自动更新也会保持活跃，即使用户没有使用节点；单凭现有架构无法准确识别这种情况。

## 数据和容量

保留 `np_source_claims` 历史记录，另建有效席位状态（有效／宽限／已释放）与最近活动时间。启用回收的来源按有效加宽限席位校验容量，历史领取仅用于统计和审计；已释放账号不再因历史领取自动绕过上限。`active_users` 仍表示有组合引用来源的启用账号，不能当作实际活跃度。界面分别说明有效席位、引用账号和历史领取。

领取、续期、回收和重新领取须沿用来源锁并在事务中校验，避免到期回收与下载并发产生超额。服务端重启后按持久化时间继续计算；一次系统故障不能把失败请求记成活动，也不能因调度延误立即跳过宽限期。

## 用户体验与恢复

进入宽限期在“我的订阅”和来源详情显示到期日及续期入口。没有已接入的通知通道时不声称会发送邮件或站外通知。

到期只释放该来源的使用资格，保留组合名称、链接和节点选择，下载过滤已释放来源，其他来源照常输出。全部节点因此不可用时返回明确错误。用户回来后主动点击“重新领取”，有空位才恢复；满额提示等待。旧链接请求不能自动重新占位。来源所有者可豁免指定账号。

上线前必须让来源所有者明确开启，并先展示预计回收名单与日期；默认维持现有历史领取规则。首版不增加排队、流量计量或验证码。
